Business Requirements
Background
Зі стрімким зростанням електронної комерції та обсягів онлайн-замовлень складські комплекси та інтернет-магазини стикаються зі збільшенням навантаження на персонал у зоні комплектації та пакування. Ручна перевірка складу замовлення пакувальником є повільною та схильною до помилок через людський фактор: недовкладення товару, переплутування артикулів, відправлення зайвих одиниць. Помилки комплектації призводять до прямих фінансових збитків через витрати на зворотну логістику, повторну доставку, виплату компенсацій та втрату лояльності клієнтів. Впровадження автоматизованої системи перевірки комплектності за допомогою розумних станцій контролю дозволяє усунути помилки до моменту герметичного пакування посилки. 
Business Opportunity
На ринку програмного забезпечення для складської логістики існують великі системи управління складом, наприклад: WMS - SAP Extended Warehouse Management, Manhattan WMS, або дороговартісні роботизовані сортувальні лінії з комп'ютерним зором. Проте такі рішення є занадто дорогими та складними у впровадженні для малого та середнього бізнесу: локальних інтернет-магазинів, аптек, виробників крафтової продукції, невеликих складів. Запропонована мною програмна система SmartPackCheck займає нішу доступних, модульних рішень для автоматизації контролю пакування. Вона не потребує дорогого промислового обладнання: перевірка базується на поєднанні серійного зчитування кодів товарів та високоточного контрольного зважування зібраного комплекту на розумній станції пакування. Монетизація проєкту передбачена за моделлю SaaS (програмне забезпечення як послуга) шляхом оформлення щомісячної підписки залежно від кількості підключених станцій пакування (IoT-терміналів) та обсягу оброблених замовлень на місяць. 
Business Objectives and Success Criteria
BO-1: Зменшити кількість помилок при комплектації замовлень не менше ніж на 95% протягом перших 3 місяців використання системи.
BO-2: Скоротити середній час перевірки одного сформованого замовлення перед пакуванням на 40% порівняно з ручною візуальною перевіркою.
BO-3: Забезпечити швидке підключення нового робочого місця пакувальника (налаштування одного IoT-пристрою) не більше ніж за 15 хвилин.
SC-1: Успішне проходження 100% тестових сценаріїв перевірки комплектності (еталонний набір, нестача позиції, надлишок позиції, невідповідність ваги) із часом відгуку системи не більше 1,5 секунди.
Customer or Market Needs
Клієнтами системи є власники інтернет-магазинів, керівники складів та оператори пакувальних станцій. Для ефективної роботи їм необхідна система, яка задовольняє такі потреби:
1. Автоматична звірка фактичного складу зібраного комплекту з даними замовлення в обліковій системі без необхідності тривалого ручного перерахунку.
2. Миттєва візуальна та звукова індикація результату перевірки безпосередньо на робочому місці пакувальника.
3. Можливість централізованого керування довідником товарів (із зазначенням еталонної ваги, габаритів та допустимої похибки) та переліком замовлень.
4. Ведення журналу всіх перевірок з фіксацією часу, відповідального оператора, очікуваної та фактичної ваги комплекту.
5. Підтримка роботи в міжнародному середовищі: вибір мови інтерфейсу: українська та англійська, та автоматична конвертація одиниць вимірювання ваги: метрична система - грами й кілограми та американська/ англійська система - унції та фунти).
6. Наявність інструментів адміністрування для резервного копіювання даних, керування ролями доступу та експорту звітів.
Business Risks
Ризик 1 - технічний: 
Розбіжність фактичної ваги товару з еталонною через зміну пакування виробником, що може викликати хибні спрацьовування. Ступінь: середній. Мінімізація: Впровадження коефіцієнта допустимої похибки ваги для кожного товару та функції швидкого калібрування еталонної ваги.

Ризик 2 - експлуатаційний: 
Втрата мережевого з'єднання на складі під час роботи пакувальної станції. Ступінь: високий. Мінімізація: Реалізація буферизації даних на стороні IoT-пристрою та повторної відправки результатів при відновленні зв'язку.

Ризик 3 - людський фактор: 
Опір персоналу новим правилам роботи через страх контролю. Ступінь: низький. Мінімізація: Максимально простий та інтуїтивний інтерфейс IoT-пристрою, що прискорює роботу пакувальника та знімає з нього фінансову відповідальність за випадкові помилки.

Vision of the Solution
Vision Statement
Для складських комплексів та компаній електронної комерції, які прагнуть усунути помилки при відправленні товарів та прискорити процес відвантаження, програмна система SmartPackCheck є інтелектуальним рішенням для контролю комплектності замовлень. Система поєднує хмарну серверну платформу управління замовленнями з автономними IoT-станціями контрольного зважування та сканування на робочих місцях пакувальників. На відміну від ручного контролю та дорогих промислових ліній, SmartPackCheck забезпечує миттєву, точну та економічно доступну верифікацію кожного комплекту перед його запакуванням. 
Major Features
Управління каталогом товарів та замовленнями: 
Створення, редагування та зберігання інформації про товари: артикул, назва, еталонна вага, допустима похибка, і склад замовлень клієнтів.
Автоматизована перевірка комплектності на IoT-станції: 
Зчитування штрих-коду замовлення, послідовне сканування позицій та контрольне зважування зібраного набору.
Математична обробка даних перевірки:
1. Розрахунок сумарної очікуваної ваги замовлення: Wочік=(wiqi)+Wтари, де wi - еталонна вага одиниці товару, qi - кількість одиниць у замовленні, Wтари - вага пакувальної коробки.
2. Розрахунок динамічного допуску похибки: W=(iqi)+ваг, де i - допустиме відхилення ваги товару, ваг - похибка тензодатчика.
3. Верифікація комплекту за умовою |Wфакт- Wочік| ≤ W та перевірка відповідності кількості відсканованих штрих-кодів.
4. Обчислення показників ефективності роботи станцій пакування (відсоток успішних перевірок з першої спроби, середній час пакування замовлення, рейтинг найбільш проблемних артикулів).
Інтернаціоналізація та локалізація: 
Підтримка української та англійської мов інтерфейсу, кодування UTF-8, зберігання часу у форматі UTC з відображенням у локальному часовому поясі користувача, автоматичний перерахунок одиниць маси: грами/кілограми  унції/фунти.
Підсистема адміністрування та захисту даних: 
Розмежування прав доступу: адміністратор, менеджер складу, оператор пакування, шифрування паролів, захист персональних даних відповідно до вимог GDPR, створення резервних копій бази даних, експорт та імпорт довідників у форматах CSV/JSON, керування конфігураціями та сертифікатами безпеки IoT-пристроїв.
Assumptions and Dependencies
Припущення: 
Кожен товар на складі має унікальний штрих-код та відому еталонну вагу.
На робочому місці пакувальника є стабільне підключення до мережі Інтернет (Wi-Fi) для обміну даними із серверною частиною.
Залежності: 
Система залежить від працездатності апаратних компонентів IoT-станції (мікроконтролера, тензодатчика з АЦП, сканера кодів) та доступності хмарного сервера розгортання.
Scope and Limitations
Scope of Initial Release
У межах першого релізу прототипу системи реалізується базовий життєвий цикл перевірки замовлення:
Функціональність серверної частини (Back-end):
Реалізація реляційної бази даних для зберігання користувачів, ролей, товарів, замовлень, складів замовлень, зареєстрованих IoT-станцій та журналу перевірок.
Надання програмного інтерфейсу (REST API) для взаємодії з клієнтськими застосунками та IoT-пристроями.
Виконання математичних розрахунків еталонної ваги, допустимих меж відхилення та формування вердикту перевірки.
Реалізація функцій адміністрування: керування обліковими записами, створення резервних копій БД, експорт/імпорт даних (CSV/JSON), керування токенами доступу пристроїв.
Підтримка локалізації (UK/EN) та інтернаціоналізації (конвертація одиниць вимірювання).
Функціональність IoT-клієнта:
Авторизація пристрою на сервері та завантаження налаштувань (одиниці вимірювання, похибка тари, мова повідомлень).
Отримання даних про поточне замовлення за його ідентифікатором (штрих-кодом).
Зчитування ваги зібраного комплекту з датчика ваги та передача телеметрії на сервер.
Локальна попередня фільтрація шумів датчика ваги (усереднення вимірювань) та миттєве відображення статусу перевірки (зелений сигнал - комплект вірний, червоний сигнал - помилка комплектації із зазначенням різниці ваги).
Scope of Subsequent Releases
У подальших версіях системи планується розширення клієнтської екосистеми:
Функціональність веб-клієнта (кабінет менеджера та адміністратора):
Візуальна панель керування - дашборд, зі статистикою ефективності пакування та графіками помилок за змінами.
Зручний графічний інтерфейс для наповнення каталогу товарів, формування замовлень та перегляду історії перевірок.
Веб-інтерфейс адміністратора для налаштування параметрів системи, управління правами користувачів та запуску резервного копіювання в один клік.
Функціональність мобільного клієнта (застосунок пакувальника):
Використання камери смартфона як мобільного сканера штрих-кодів для прив'язки замовлення до конкретної IoT-станції пакування.
Отримання миттєвих сповіщень керівником зміни у разі виявлення критичної кількості помилок на певній станції.
Можливість швидкого фотографування дефектного або невідповідного комплекту для додавання фотозвіту до журналу перевірок.
Limitations and Exclusions
1. Система не керує фізичними маніпуляторами або роботизованими руками для перекладання товарів — вона виконує функцію інтелектуального контролю та блокування підтвердження пакування при виявленні невідповідності.
2. У початковій версії не реалізується розпізнавання товарів за допомогою відеокамер та нейронних мереж (використовується метод вагового та штрих-кодового контролю).
3. Не передбачена пряма інтеграція з платіжними шлюзами та фіскальними реєстраторами.

Operating Environment
Умови експлуатації та вимоги до середовища:
Географічний розподіл: користувачі - адміністратори, менеджери, та складські комплекси з IoT-станціями можуть знаходитися в різних містах та часових поясах. Усі часові мітки зберігаються на сервері у стандарті UTC та конвертуються у локальний час клієнта.
Режим роботи та доступність: система повинна функціонувати цілодобово (24/7) з допустимим часом простою не більше 1% на місяць для проведення технічного обслуговування.
Продуктивність: максимальний час відповіді серверного API на запит перевірки ваги від IoT-станції не повинен перевищувати 1,5 секунди, щоб не затримувати конвеєр пакування.
Безпека та цілісність даних: між клієнтами, IoT-пристроями та сервером здійснюється за захищеним протоколом HTTPS з використанням токенів автентифікації (JWT / API-ключів). Паролі користувачів зберігаються у хешованому вигляді, забезпечується регулярне резервне копіювання бази даних.
Програмні засоби та інструменти розробки (технологічний стек):
Мова програмування та фреймворк серверної частини: 
C# (.NET 8) та фреймворк ASP.NET Core Web API (середовище розробки - Microsoft Visual Studio 2022), що забезпечує високу продуктивність, сувору типізацію та автоматичну генерацію документації OpenAPI.
Система керування базами даних: 
Microsoft SQL Server 2022 (адміністрування та проєктування через SQL Server Management Studio 2022); для об'єктно-реляційного відображення даних використовується Entity Framework Core.
Програмне забезпечення IoT / SmartDevice клієнта: 
Мова програмування C# (.NET 8) у середовищі Visual Studio Code (реалізація програмного модуля інтелектуального терміна+ла зважування та сканування). Протокол обміну даними із серверною частиною - HTTP/HTTPS (REST API) у форматі JSON.
Веб-інтерфейс та допоміжні інструменти: HTML, CSS, JavaScript (для базового клієнтського інтерфейсу), Swagger UI / Postman (для тестування прикладного програмного інтерфейс), PlantUML (для побудови UML-діаграм), GitHub (для контролю версій коду).
